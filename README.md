# 3색 바이브코딩

수업 · 사회정서교육 · 업무 웹앱을 모아 공개하는 페이지와 마스터 관리자.

## 실행

Node.js 24 이상, npm, Chromium, curl이 필요합니다. 이 클라우드에는 설치되어 있습니다.

```sh
cd /workspace/vibe
npm ci
npm start
```

초기 관리자 비밀번호는 **4021**입니다. 코드를 수정하거나 별도 설정할 필요 없이 `/admin`에서 로그인할 수 있습니다. 비밀번호는 첫 실행 시 해시로 저장되며 재시작 시 기존 비밀번호를 유지합니다. 변경하려면 `npm run admin:password`를 실행하세요. 터미널 입력은 화면에 표시되지 않으며, 비밀번호를 변경하면 기존 로그인은 모두 해제됩니다. 자동화에서는 최초 실행 시 `ADMIN_PASSWORD`로 다른 비밀번호를 주입할 수 있습니다. 이미 설정한 비밀번호는 환경 변수로 덮어쓰지 않습니다.

공개 페이지는 `/`, 관리자는 `/admin`입니다. 개발 중 자동 재시작은 `npm run dev`를 사용합니다. 필요한 설정은 `.env.example`을 참고해 로컬 `.env`에 추가하세요. 비밀번호나 `.env`를 Git에 커밋하지 마세요.

## 관리자

- 이름, 주소, 분류, 설명을 등록·수정합니다.
- 공개 여부를 끄면 공개 목록과 공개 API에서 제외됩니다.
- 드래그 또는 위아래 버튼으로 순서를 변경합니다. 모바일에서도 버튼을 사용할 수 있습니다.
- JPG, PNG, WebP 파일을 최대 4MB까지 업로드할 수 있습니다.
- 직접 올린 이미지가 우선이며, 자동 썸네일로 되돌릴 수 있습니다.
- 등록 및 주소 변경 시 첫 화면을 자동 캡처합니다. `다시 캡처`로 갱신합니다.

## 저장 및 배포

데이터는 기본 `data/vibe.sqlite`, 이미지는 `data/thumbnails/`에 저장됩니다. 서버를 재시작해도 유지됩니다. 배포 시 `DATA_DIR`을 영구 볼륨으로 연결하고 전체 디렉터리를 함께 백업하세요. 여러 서버가 동일 SQLite 파일을 동시에 공유하는 구성은 사용하지 마세요. 실행 중 백업은 SQLite backup API를 사용하거나 서버를 중지한 뒤 디렉터리를 복사하세요.

HTTPS로 배포하고 `.env.example`의 `APP_ORIGIN`, `TRUST_PROXY`, `COOKIE_SECURE`를 배포 구성에 맞게 설정하세요. 관리자 페이지에는 검색 제외 태그가 있으며 인증은 서버에서 확인합니다. 로그인은 12시간 유지되며, IP별 실패 횟수를 제한합니다. 역방향 프록시를 사용할 경우 외부에서 앱 서버에 직접 접근하지 못하게 하고 프록시 한 단계 구성에서만 `TRUST_PROXY=1`을 사용하세요.

이 저장소는 웹앱 링크와 썸네일을 관리합니다. 링크 대상 웹앱 자체를 업로드하거나 호스팅하는 기능은 포함하지 않습니다.

## 자동 썸네일과 네트워크

Chromium 경로는 `CHROMIUM_PATH`로 지정할 수 있습니다. 기본적으로 `/usr/bin/chromium` 등을 탐색합니다. Linux 컨테이너에서는 Chromium을 격리된 환경에서 실행하세요. 서버의 HTTP(S) 프록시와 TLS 검증을 유지합니다.

캡처 전에 주소를 검증하고 내부·루프백 IP를 차단합니다. 하위 리소스와 리다이렉트도 같은 검증을 거칩니다. 로컬 DNS가 차단된 프록시 환경에서는 TLS 검증을 유지한 `https://dns.google/resolve` 공개 DNS 조회를 사용하며, 조회 결과에도 동일한 IP 검증을 적용합니다. 조회가 실패하면 캡처를 중단합니다.

클라우드 네트워크 설정에서 `dns.google` 및 **등록할 웹앱과 그 리소스의 도메인**을 허용해야 합니다. 현재 환경에서는 `dns.google` CONNECT가 HTTP 403으로 차단되어 실제 원격 캡처 검증이 실패했습니다. 정책 적용 후 관리자에서 `다시 캡처`를 눌러 재시도하세요. 로그인, 봇 방지, 접속 차단 페이지는 직접 이미지를 올리는 편이 정확합니다. 캡처 실패해도 링크 등록과 직접 이미지 업로드는 가능합니다.

## 검증

```sh
npm test
```

임시 데이터베이스와 3147 포트를 사용합니다. 인증·CSRF·등록·숨김·수정·정렬·썸네일 업로드·삭제·재시작 후 유지, 데스크톱/모바일 UI를 확인합니다. 실제 GitHub 첫 화면 캡처도 포함하므로 네트워크 전제 조건이 충족되어야 전체 통과합니다. Chromium이 `/usr/bin/chromium`에 필요합니다. 테스트용 항목과 비밀번호는 임시 디렉터리에만 저장하고 끝나면 삭제합니다. 화면 캡처는 Git에서 제외된 `test-results/`에 생성됩니다.

실제 웹앱 데이터는 기본으로 비어 있습니다. 테스트용 예시는 공개 데이터에 추가하지 않습니다.
